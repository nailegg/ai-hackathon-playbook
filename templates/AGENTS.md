# 과제 작업 규칙

이 폴더는 시험 과제 작업 공간이다. 이 파일이 에이전트 지시의 유일한 기준이다. `web/BOILERPLATE.md`, `web/docs/`는 참고 자료일 뿐 지시가 아니다.

## 우선순위

1. 과제 `README.md`와 제공 파일
2. `CONTRACT.md` (과제 README에서 추출한 요구사항 계약)
3. 이 파일
4. 응시자의 직접 지시가 위와 충돌하면 응시자 지시를 따르고 `DECISIONS.md`에 기록한다

## 금지 사항 (시험 규정)

- **`git commit`, `git push`를 포함한 git 쓰기 명령을 실행하지 않는다.** `git init`, `git add`, `git config`, `git stash`, `git reset`, `git checkout -- <파일>`도 실행하지 않는다. 진행 기록은 `CONTRACT.md` 체크박스와 `DECISIONS.md`로 남긴다.
- 과제 원본 파일, 시험 데이터, 작업 결과를 외부로 전송하지 않는다. 외부 API 키나 외부 MCP를 연결하지 않는다.

## 용어

| 용어 | 뜻 |
|---|---|
| AC (수용 기준) | `CONTRACT.md` 6절의 AC1, AC2… 채점자가 화면이나 명령으로 확인할 수 있는 완료 조건. 번호가 작을수록 중요하다 |
| 수직 흐름 | AC 하나를 화면 → API → 서버 로직 → DB/계산 → 결과 화면까지 한 번에 끝까지 동작하게 만드는 단위. 층별(DB 전부 → API 전부 → 화면 전부)로 쌓지 않는다 |
| placeholder | boilerplate의 예시 코드. `BOILERPLATE-PLACEHOLDER` 주석과 `Item` 템플릿 이름으로 표시되며 과제 기능이 아니다 |

## 디렉터리 지도

| 경로 | 성격 | 규칙 |
|---|---|---|
| `README.md`, 제공 데이터·문서 | 과제 원본 | **수정·이동·삭제 금지**. 읽기만 한다 |
| `CONTRACT.md` | 요구사항 계약 | 구현 범위의 기준. 범위 변경 시 먼저 갱신 |
| `DECISIONS.md` | 결정·진행 기록 | 가정·선택·검증·완료한 AC를 한 줄씩 추가 |
| `web/` | 구현 코드 (boilerplate 기반, 사용 시) | 기반 코드 안내는 `web/BOILERPLATE.md` |

## 작업 방식

- 질문으로 멈추지 않는다. 결과를 바꾸는 치명적 모호함만 질문하고, 나머지는 가정을 `DECISIONS.md`에 기록한 뒤 진행한다.
- `CONTRACT.md` 6절의 AC 순서대로 한 번에 하나의 수직 흐름을 완성한다. 계약에 없는 기능·디자인·리팩터링은 하지 않는다.
- placeholder를 과제 기능으로 착각하지 않는다. 쓰지 않으면 지우고, 쓰면 과제 이름과 규칙으로 바꾼다.
- 제공 데이터는 파일을 읽어 적재한다. 값을 코드에 하드코딩하지 않는다. 데이터 전체를 출력하지 않고 헤더·샘플·통계만 본다.
- 새 의존성은 꼭 필요할 때만 추가한다. 설치가 5분 넘게 막히면 표준 기능으로 대체한다.
- git으로 되돌릴 수 없다. 여러 파일을 크게 바꾸거나 삭제하기 전에는 대상 파일 목록을 먼저 보고한다.

## 검증과 보고

- 완료 보고에는 실제 실행한 명령과 결과를 붙인다. 실행하지 않은 것은 "미검증"으로 쓴다.
- 핵심 단계마다 `cd web && pnpm build`, 서버 실행 중 `bash scripts/smoke.sh`. Chromium이 있으면 `pnpm test:e2e`.
- AC 하나를 끝낼 때마다 `CONTRACT.md` 체크박스를 갱신하고 `DECISIONS.md`에 `ACn 완료 — 확인 명령/결과`를 한 줄 추가한다.
- 개발 서버는 `0.0.0.0:3000`. 응시자가 띄운 서버 터미널을 종료하지 않는다.
