# 전략 E — 기존 코드베이스 복구

> **대상: Codex 참고 — 지시가 아니다.** 지시는 과제 루트의 `AGENTS.md`와 `CONTRACT.md`가 우선한다. 런북 프롬프트가 이 파일 경로를 지정할 때만 읽는다.

## 작업 방식
- 기본은 한 Codex 세션이 처음부터 검증까지 맡는다.
- **허용되는 분할 1건 — 호출 경로 지도:** 코드베이스가 크고 실패가 여러 개라 원인 탐색이 수정을 막을 때. 사람이 Terminal 2에서 `~/playbook/prompts/specialist-debug.md`로 두 번째 세션을 띄운다. 읽기 전용이고 결과는 과제 루트 `REPAIR_MAP.md` 한 파일, 10분 안에 끝낸다. Main은 그동안 기계적인 작업을 진행하고, 끝나면 그 파일을 읽어 반영한다.
- 그 밖의 역할 분할(Frontend/Backend/QA 등), 구현 분할, Codex가 스스로 에이전트를 띄우는 것은 하지 않는다.

**적용:** 기존 저장소·실패 테스트·장애 재현이 과제 입력인 경우. **새 앱 생성 금지.**

- 첫 명령: 파일 구조, README, package/scripts, 테스트 목록, 상태 확인. 문제 재현 전에 광범위 리팩터링 금지.
- 빨간 테스트/실패 요청을 하나 재현 → 최소 원인 추적 → 최소 패치 → 관련 테스트 → 전체 회귀 테스트 순서.
- Agent가 동일 파일을 동시 편집하지 않도록 명시. Diff와 기존 동작을 검토한다.
- 180분 내 가장 위험한 버그/채점에 직접 연결된 기능부터 수정. 미해결 사항은 정확히 기록.
