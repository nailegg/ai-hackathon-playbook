# 전략 D — 데이터 분석·의사결정 지원

> **대상: Codex 참고 — 지시가 아니다.** 지시는 과제 루트의 `AGENTS.md`와 `CONTRACT.md`가 우선한다. 런북 프롬프트가 이 파일 경로를 지정할 때만 읽는다.

## 작업 방식
- 기본은 한 Codex 세션이 처음부터 검증까지 맡는다.
- **허용되는 분할 1건 — 데이터 품질 점검:** 데이터가 여러 파일이거나 누수·결측·키 불일치가 결론을 바꿀 수 있을 때. 사람이 Terminal 2에서 `~/playbook/prompts/specialist-data.md`로 두 번째 세션을 띄운다. 읽기 전용이고 결과는 과제 루트 `DATA_QUALITY.md` 한 파일, 10분 안에 끝낸다. Main은 그동안 기계적인 작업을 진행하고, 끝나면 그 파일을 읽어 반영한다.
- 그 밖의 역할 분할(Frontend/Backend/QA 등), 구현 분할, Codex가 스스로 에이전트를 띄우는 것은 하지 않는다.

**적용:** 원인 분석, 예측, 그룹 비교, 정책 제안, 대시보드/리포트.

- 문제의 **의사결정 질문과 평가 지표**부터 확정. 목표변수/시간 단위/관측 단위 혼동 금지.
- 첫 20분 내 스키마, 결측, 중복, 분포, 시간 순서, 데이터 누수 가능성 확인.
- 먼저 설명 가능한 baseline과 교차검증/시간 분리, 이후 필요 시 복잡한 모델.
- 상관관계를 인과로 주장하지 않는다. 데이터 크기, 클래스 불균형, 누락의 한계 기록.
- UI가 필수라면 최소 시각화 2~3개를 실제 분석 결과에 연결. 디자인을 위한 그래프 남발 금지.
- 산출물: 재현 가능한 스크립트, 지표·시각화, 가정, 실패 사례와 개선 제안.
