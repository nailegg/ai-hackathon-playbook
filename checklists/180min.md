# 180분 타임박스 — 분 단위 강제 전환

| 시점 | 반드시 확보할 것 | 안 되면 |
|---|---|---|
| T+0~15 | README·데이터·필수 산출물·유형·Hard constraints·최소 실행 흐름 | 모호함 중 치명적인 것만 실무자에게 질문 |
| T+15~45 | 실행환경, 데이터 연결, 최소 프로젝트 구조 | 설치 실패 도구·화려한 스택 포기 |
| **T+70** | 최소 end-to-end: 화면/API/DB 또는 입력→결과 파일 | 나머지 기능 중단, 첫 흐름 복구 |
| **T+135** | 핵심 가치(OR/RAG/분석/수리)가 실제 작동, baseline 지표 | 개선 알고리즘·선택 UI 포기 |
| **T+160** | 필수 빌드·실행·고위험 테스트 및 제출 파일 확인 | 기능 추가 금지, 복구·제출 집중 |
| **T+170** | 제출 미리보기 시작 권장 | 남은 10분 내 확정 진행 |
| T+180 | 과제 제출 확정, 이후 별도 서술형 단계 | 서술형에서는 AI·복사붙여넣기 금지 |

## 네 가지 보편 규칙
- **최소 작동 우선:** 첫 45~70분에 실제 입출력이 나오는 baseline.
- **역할 분할 최소화:** Main이 통합. Specialist는 독립적 고난도 분석일 때만.
- **도구 포기 기준:** 설치·승인/연결 반복은 한도(예: 5분)를 정하고 fallback.
- **검증은 실제 실행:** `build`, API smoke, independent constraints; 미실행은 미검증.

## 체크포인트 지시
```text
현재 남은 시간과 README 필수 항목을 기준으로 완료·미완료·치명적 오류를 TASKS.md에 10줄 이내로 요약하고, 다음 작업 하나를 추천해라. 부차 기능을 추가하지 마라.
```

**주의:** 시간 배분은 권장 휴리스틱. 기존 코드 수리, 무UI 알고리즘 과제에서는 실제 플로우와 체크를 조정한다.

## 예상 밖 과제 시 전환
A–G 분류에 맞지 않거나 새 출력 형식이 주어지면 [Unknown Task Mode](../strategies/unknown-task.md) 사용. T+10 산출물/입력/검증기 확정, T+25 위험 가정 실험, T+45 첫 샘플 결과, T+70 전체 입력→출력. **아는 스택을 강제로 적용하지 않는다.**
